Course: HTML CSS JavaScript track
Lesson: html10 Site Quality and Publishing
Type of document: extension task

In one sentence:
This optional task for fast finishers has you audit your live GitHub Pages site with two free web tools, fix three real problems they find, and report the before and after results.

Main ideas:
1. It is extra credit with no points and no rubric, and you should only start it after finishing the regular html10 tasks.
2. It assumes your site is already live on GitHub Pages. You audit it the way a professional would, using web-based tools, so browser developer tools are not needed.
3. PageSpeed Insights (pagespeed.web.dev) is Google Lighthouse running in the cloud. You give it your live URL and it scores Performance and Accessibility, among other things.
4. WAVE (wave.webaim.org) is an accessibility checker that lists errors and alerts on a page.
5. Real fixes it suggests: compress a large image, add missing alt text, fix a failing contrast ratio, or add a meta description. A fix must genuinely solve the problem, not just hide or suppress the warning.

Key terms:
PageSpeed Insights — Google's online tool that runs Lighthouse on a live URL and reports scores.
Lighthouse — Google's automated audit for performance, accessibility and more.
WAVE — WebAIM's web accessibility evaluation tool, which reports errors and alerts.
finding — one specific problem reported by an audit tool.
suppressed — hidden from the tool without actually being fixed; not allowed here.

What you are asked to do:
1. Run your live URL through PageSpeed Insights and record your Performance and Accessibility scores.
2. Run it through WAVE and record the errors and alerts.
3. Choose three real findings across the two tools and fix them.
4. Re-run both tools.
Commit a file named html10_ExtensionAudit_lastname.md (with your last name) that contains the before scores and findings, what you fixed and how, and the after scores and findings. Also push the actual fixes.
Done when: before and after results are recorded for both tools; three findings are genuinely fixed, not suppressed; the report explains each fix in a sentence or two; everything is pushed to GitHub.

Watch out for:
- You need a live URL first, so finish the html10e publishing task before this.
- Record the before results before you change anything, or you will have nothing to compare.
