Summary of: html10_SeoDIYTask.md
Course: HTML CSS JavaScript track
Lesson: html10 Site Quality and Publishing
Type of document: DIY task

In one sentence:
In this independent project you audit one of your own earlier websites for SEO and accessibility problems, record them in an audit report, fix them in priority order, and test the results.

Main ideas:
1. Estimated time is 60 to 90 minutes. Pick a project with multiple pages or substantial content and images; forms or interactive parts are a bonus. It should be something you are proud of, and not a tiny one-page project. The suggested examples use the old lesson numbers: a portfolio, business site, blog, product page or landing page.
2. The SEO audit and accessibility audit are yes-or-no checklists; every No is a problem to fix. The full items are listed under What you are asked to do.
3. Fixes are done in three priority levels, most important first (listed below).
4. Testing methods:
- Keyboard test: open the project, stop using the mouse or trackpad, and use only Tab (next), Shift plus Tab (previous), Enter (activate) and arrow keys (move inside components). Check that you can reach every clickable element and that focus is always visible.
- Contrast test: at the WebAIM Contrast Checker, test every text and background color pair, record the ratios in your report, and fix any below 4.5 to 1.
- Optional screen reader test: use NVDA (free for Windows), VoiceOver (Mac) or Narrator (Windows) and check that headings, links and form labels make sense when read aloud.
5. A before-and-after example. The before page has an empty title, no meta description, a header, nav and main built from divs, navigation as divs with onclick, two images without alt text, and two h1 elements (Welcome and Product 1). The after page has lang="en"; the title "Quality Products Online | AccuRate Shop"; a meta description; charset and viewport meta tags; body text #333 on white; a 3-pixel blue focus outline on buttons, links and inputs; real header, nav, main, section, article and footer elements; one h1 with h2 and h3 below it; real a links; descriptive alt text; and a real Buy Now button.
Code: button:focus, a:focus, input:focus { outline: 3px solid blue; }
This rule shows a thick blue outline around whichever button, link or input has keyboard focus.
6. Tips: start with Priority 1, test as you fix, use WAVE, Lighthouse and the WebAIM checker, document everything (the report is half the assignment), audit every page and not just the home page, and ask for help when stuck.
7. Resources: WAVE (wave.webaim.org), the WebAIM Contrast Checker, Google Lighthouse (in Chrome DevTools, opened with F12), NVDA, the WCAG quick reference, and the Moz SEO guide.

Key terms:
audit report — your written record of each issue, its location, the fix and its status.
decorative image — an image that adds no information; it should have an empty alt attribute, written alt="".
fieldset and legend — tags that group related form fields and give the group a caption.
role attribute — tells assistive technology what a custom widget is.
skip navigation link — a link at the top that jumps keyboard users past the menu to the main content.
required attribute — marks a form field as mandatory.

What you are asked to do:
SEO audit checklist:
- Title and meta: title exists and is under 60 characters; includes the main keyword; is not generic like "Home" or "Page 1"; meta description exists; is 150 to 160 characters; is compelling and describes the content; includes a call to action (optional but good).
- Images: all have alt text; alt text is descriptive, not "image" or "picture"; describes the content clearly; is 100 to 125 characters at most; decorative images such as spacers or borders can have empty alt.
- Headings: exactly one h1; h2s describe main sections; h3s describe subsections where needed; no skipped levels; headings match the visual importance of content.
- Structure: uses header, nav, main, article or section, and footer; avoids excessive divs.
- URL and content: descriptive URL, not /page1 or /index123; original content; 200 or more words for pages and 300 or more for articles; keywords natural in title, h1, first paragraph and headings; content answers the likely search.
- Technical: valid HTML5; links are real a elements, not divs with onclick; descriptive link text, not "click here"; images optimized, not 5 MB or more.
Accessibility audit checklist:
- Color and contrast: good contrast; dark on light or light on dark; no light gray on white; meaning not shown by color alone; verify 4.5 to 1 with the WebAIM checker.
- Images: meaningful alt text; decorative images have empty alt; icons have aria-label; information not conveyed by color alone.
- Forms: every input has a connected label using for and a matching id; clear labels; required fields marked visually and with the required attribute; clear, specific error messages.
- Interactive elements: buttons are button elements or input type="button", not divs; links are a elements; buttons have clear text; buttons and links announce their purpose to screen readers.
- Keyboard: fully usable with Tab, Shift plus Tab and Enter; logical tab order; everything reachable; focus indicator visible and not hidden by CSS.
- Headings: one h1, logical h2 and h3, no skipped levels.
- Semantic HTML: proper button, a, header, nav and main; no div or span for interactive elements; forms use form, label and input; lists use ul, ol and li.
- ARIA: icon buttons (close, menu, search) have aria-label; complex widgets have appropriate role attributes; grouped form sections use fieldset and legend; a skip navigation link (optional but recommended).
- Readability: body text at least 16 pixels; line spacing 1.5 or more; reasonable line length; clear headings.
Create AUDIT_REPORT.md in your project folder. It must include: project name; audit date; each SEO issue with location, problem, fix and status (Not Started, In Progress or Fixed); each accessibility issue in the same format, plus current and target contrast ratios for contrast issues; a summary of total, fixed and remaining issues for SEO and for accessibility; testing done (WAVE, keyboard-only test, contrast test, Lighthouse, and optional screen reader test); and notes.
Fix in priority order:
- Priority 1: title tags on every page; meta descriptions on every page; alt text on all images; color contrast; connected form labels.
- Priority 2: heading hierarchy; semantic tags; real button elements; real a elements; focus indicators.
- Priority 3: aria-labels on icon buttons; form usability; image optimization; content improvements.
As you fix, update each status to Fixed in the report and add before-and-after code examples (for example an empty title replaced by a descriptive one, and an image given descriptive alt text).
Submit: 1. your fixed project files (HTML, CSS, assets); 2. AUDIT_REPORT.md with all issues, how each was fixed, before and after code, and test results; 3. optionally a screenshot of the contrast checker showing improved ratios.
Grading rubric criteria (no point values are given): SEO audit completeness, 10 or more SEO issues found and documented; accessibility audit completeness, 10 or more accessibility issues documented; SEO fixes, 8 or more priority SEO issues fixed correctly; accessibility fixes, 8 or more priority accessibility issues fixed correctly; documentation quality, a clear report with before and after examples; testing and verification, evidence of keyboard and contrast testing.

Watch out for:
- The report counts as half the assignment, so do not skip documentation.
- Audit every page, not only the home page.
- Heads up: the example lesson numbers (HTML 1 to 11, portfolio in HTML 5, and so on) are old course numbering. Choose any substantial project from html01 to html09 instead.
- Correction: a purely decorative image (a spacer or border) should have an empty alt, written alt="", so screen readers skip it. The SEO checklist line words this confusingly ("No decorative images ... those can have empty alt"), but the accessibility section states the rule correctly.
- Heads up: the before-and-after example's issue list mentions missing form labels and light gray text, but the before code has no form and no gray text. Treat those two items as general reminders (connect labels with for and id, use dark text such as #333 on white), not problems to find in that code.
- ARIA items beyond aria-label (role, fieldset grouping) appear here, but the unit guide says only aria-label is on the exams.
