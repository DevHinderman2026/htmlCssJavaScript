In one sentence:
This study guide collects the vocabulary, key patterns, attribute reference, and state competencies for the HTML Forms lesson (its review questions are left out of these study notes).

Main ideas:
1. Form structure. Every form starts with the form element, which has an action attribute (where the data goes) and a method attribute (GET or POST). A submit button inside the form sends it.
Code: <form action="/submit-page" method="POST">
This starts a form that sends its data to /submit-page using POST.

2. Two ways to connect a label to an input.
Method 1, for and id pairing: the label's for attribute matches the input's id.
Code: <label for="username">Username:</label> <input id="username" name="username" type="text">
The for value and the id value are both "username", so the two are linked.
Method 2, wrapping: put the input inside the label element. This is handy for checkboxes, for example a checkbox followed by the words "I agree to terms", all inside one label.

3. Input types cheat sheet: text (regular text), email (checks email format), password (hides characters), number (numbers only), date (date picker), tel (telephone), url (website address), search (search field).

4. Radio versus checkbox. Radio buttons allow one choice only; checkboxes allow several. Both use the same name for every item in a group. Visually a radio is a circle and a checkbox is a square. Radios suit things like size or rating; checkboxes suit things like interests, agreeing to terms, or choosing features.

5. Form styling basics. Give input, textarea and select padding of 8 pixels, a 1-pixel light gray border, 4-pixel rounded corners and a 16-pixel font. Make labels display: block with a top margin and bold weight. Give buttons padding, a blue background, white text, no border, rounded corners and cursor: pointer, and darken the blue on hover.

6. Attribute quick reference (attribute, where it is used, what it does):
- action, on form: where to send data, for example action="/submit".
- method, on form: how to send, GET or POST.
- type, on input: the kind of input, for example type="email".
- name, on input controls: identifies the field in the submitted data.
- value, on input controls: the data sent, or default text.
- for, on label: connects to an input's id.
- placeholder, on input and textarea: hint text.
- required, on input controls: field is mandatory.
- id, on any element: unique identifier.
- rows, on textarea: number of visible rows.
- cols, on textarea: number of visible columns.
- tabindex, on any focusable element: tab order.

7. ODE competencies covered:
- 6.4.1 Design forms from specifications: match project requirements, choose the right input types, plan layout.
- 6.4.2 Add forms to web pages: insert form tags correctly, set action and method, keep the HTML valid.
- 6.4.3 Use text fields, radios, checkboxes and dropdowns: text and email inputs, correctly named radio groups, checkbox groups, and select with option.
- 6.4.4 Apply the form action concept: what action does, GET versus POST, and where data is submitted.
- 6.4.5 Create submit and reset buttons with the right button types.
- 6.4.6 Style forms with CSS: padding, margins, styling labels, inputs, buttons and fieldsets, attractive and responsive layouts.
- 6.5.9 Incorporate forms into web pages: embed forms in page content, combine them with other HTML, and build multi-section forms with fieldsets.

8. Key takeaways: forms collect user data through many input types; always use labels because they improve accessibility and usability; radio means one choice and checkbox means many; action and method control where and how data is sent; styling forms means targeting inputs, labels, buttons and fieldsets with CSS; use for and id, proper labels and semantic HTML for accessibility.

Key terms:
form — container element that collects user input.
action — form attribute naming where the data is sent.
method — form attribute naming how data is sent, GET or POST.
GET — sends the data in the URL; visible and limited in size.
POST — sends the data in the message body; hidden from the address bar and allows larger amounts.
input — control for single-line text, numbers, dates and more.
type — input attribute that sets the kind of data.
text — basic text entry type.
email — input type with built-in email checking.
password — input type that hides characters as you type.
number — input type that accepts only numbers.
date — input type that shows a date picker.
label — element that describes a form control and improves accessibility.
for — label attribute that connects it to an input by id.
placeholder — hint text inside an input that disappears when the user types.
required — makes a field mandatory before submission.
radio — input type allowing ONE choice from a group.
checkbox — input type allowing MULTIPLE choices.
select — a dropdown menu, filled with option elements.
option — a single choice inside a select.
textarea — control for multi-line text.
fieldset — groups related controls together.
legend — the title of a fieldset.
submit — button type that sends the form data to the action URL.
reset — button type that clears all fields.
tabindex — sets the order fields are focused when Tab is pressed.

Watch out for:
- A placeholder disappears once the user types, so it cannot replace a label.
- Radios and checkboxes in a group share one name; each gets its own value.
