Summary of: html02_DIYTask.md
Course: HTML CSS JavaScript track
Lesson: html02 Semantic HTML
Type of document: DIY task (independent project with self-assessment rubric)

In one sentence:
Build your own complete recipe page from scratch, for a food, drink, or craft of your choice, that uses the semantic page regions, strong and em, and all four list types, and that passes the W3C validator.

Main ideas:
1. This independent project shows you have mastered semantic structure, text formatting, and lists from lesson 02.
2. The "recipe" can be food (pizza, brownies, tacos, pasta, smoothie bowl, salad, soup), a drink (coffee drink, cocktail, smoothie, specialty tea), a craft (candle, slime, tie-dye, bath bomb), or something else (DIY cleaning solution, terrarium, plant propagation).
3. Plan before coding: outline the name and description, the ingredients (for the ul), the instructions (for the ol, with possible nesting), nutrition or timing info (for the dl), and related content for the aside.
4. The suggested structure: the HTML5 boilerplate with meta charset, viewport meta tag, and a title of your recipe name; then in the body a header, a nav, a main containing a section and an aside, and a footer.
5. Where each list fits: ul for ingredients or items with no order; ol for numbered steps; at least one nested list, such as prep sub-steps inside a main step; dl with dt and dd for timing or nutrition.
6. Text formatting examples: strong for something like "Important: Use fresh ingredients"; em for something like "This step is critical".
7. Validate and test: open it in a browser, validate at validator.w3.org, open DevTools with F12 and check the console for errors, and if you use a screen reader, listen to how it reads.

Key terms:
header, nav, main, section, article, aside, footer — semantic page regions.
strong, em — importance and emphasis.
ul, ol, li — unordered list, ordered list, list item.
Nested list — a list inside an li of another list.
dl, dt, dd — description list, term, description.
Validator — validator.w3.org, which checks your HTML for errors.
DevTools — browser developer tools (F12) with an error console.

What you are asked to do:
Content requirements:
1. A real recipe with a name and description, prep and cook times, and yield or servings.
2. Semantic structure: a header with the site or recipe title and a tagline; a nav with at least 3 links; a main wrapping the primary content; section elements grouping recipe parts; article for individual components or variations (optional but recommended); an aside with related content such as tips, substitutions, or links; a footer with copyright and contact info.
3. Text formatting: at least 3 uses of strong, at least 2 uses of em, and no b or i tags.
4. All four list types: a ul, an ol, at least one nested list, and a dl.
5. Valid HTML5: doctype, html, head, and body tags; all tags closed; passes validator.w3.org.
File name: html02_DIY_YourName.html, replacing YourName with your name or chosen title.
Self-assessment rubric (mark Yes, Partial, or No; no point values are given): valid HTML5; header with title and tagline; nav with 3 or more links; main wraps primary content; section groups recipe content; ul present; ol present; nested list present; dl present; at least 3 strong; at least 2 em; no b or i; aside with related content; footer with copyright and contact; all tags closed; page displays correctly.
Submission checklist: file named html02_DIY_YourName.html; validates with no errors; header, nav, main, section, aside, and footer all used; all four list types present; strong and em used; no b or i; opens properly in a browser; recipe is your own or properly cited if adapted.
Optional stretch challenges: multiple article elements for variations or related recipes; more complex nesting such as ingredients grouped by category; extra description lists for timing, servings, and substitutions; figure and figcaption if you add images; screen reader testing.
After finishing: compare with the solution file html02_DIYTask_Solutions.html, ask your instructor for feedback, and commit and push your work to your GitHub repository.

Watch out for:
The document's common mistakes:
1. Forgetting semantic elements.
2. Using b and i instead of strong and em.
3. Incorrect nesting: nested lists must be inside li tags, not directly inside ol or ul.
4. Unclosed tags.
5. Using ol when order does not matter.
6. Leaving out the description list; all four list types are required.
Heads up: developer tools (F12) are turned off on student computers, so use the W3C validator at validator.w3.org to check for errors instead. The solution file html02_DIYTask_Solutions.html is not in the lesson folder, so ask Mr. McMaster for feedback instead of comparing.
