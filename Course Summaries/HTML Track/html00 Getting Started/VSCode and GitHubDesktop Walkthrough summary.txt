In one sentence:
This day-two walkthrough teaches the parts of VS Code, installs three extensions, and has you create a Markdown file and a Hello World HTML file in your github-desktop-test repo, push them with GitHub Desktop, and compare the repo on GitHub before and after.

Main ideas:
1. The loop for the whole year. Edit, save, commit, push, refresh GitHub, and see that your change is there. Every later lesson repeats this loop.
2. Two tools, two jobs. VS Code (Visual Studio Code) is a code editor, a smart text editor built for writing code. It is where you write. GitHub Desktop is where you save snapshots (commits) and sync them up to GitHub.
3. Parts of the VS Code window. The Activity Bar is the column of icons on the far left that switches views: Explorer (your files), Search, Source Control, and Extensions. The Explorer lists the files and folders you have open. The Editor is the large central area where you type. Tabs across the top are your open files; a tab marked with a dot means that file has unsaved changes, and saving with Ctrl+S clears it. The Status Bar along the bottom holds information and buttons, including Go Live later. The Command Palette (Ctrl+Shift+P) lets you run almost any command by typing its name.
4. Install extensions. Open the Extensions view (Ctrl+Shift+X), search each name, choose Install, and check the publisher so you get the right one. Live Preview by Microsoft previews web pages inside VS Code. Live Server by Ritwick Dey opens your page in a browser and refreshes it automatically every time you save. Convert Markdown to PDF by Alvaro Orellana turns a Markdown file into a PDF.
5. Open the test repo. In GitHub Desktop, make sure the Current Repository is github-desktop-test, then choose Open in Visual Studio Code. If VS Code shows Restricted Mode, choose Manage, then Trust. The Explorer should show README.md and githubDesktopTest.md from the day before.
6. Why open a folder rather than a single file. VS Code works best with the whole project folder open: the Explorer shows everything in the repo and Git can track it all. If you open things the wrong way, the folder can look empty even when it is not.
7. Record the "before" state on GitHub. Use View on GitHub in GitHub Desktop. Note that the README is displayed on the repo home page, that the files are README.md and githubDesktopTest.md, and roughly what the commit count says. Leave that browser tab open.
8. Create a Markdown file. Make a new file named myFirstMarkdown.md. The class naming style is lowerCamelCase: first word lowercase, each later word capitalized, no spaces. Fill it with an About Me page using headings and lists: your name, your top three songs with artists, favorite food, movie or show, and game or hobby, the best thing you did this summer, what you would do with a free day, something you want to learn this year, and one goal for the school year. Save, then preview the formatted version with Ctrl+Shift+V. Optionally export a PDF through the Command Palette command "Markdown PDF: Export (pdf)".
9. Markdown basics from the cheat sheet. A line starting with a number sign (the pound or hash symbol) is a heading. Text wrapped in two asterisks on each side is bold; one asterisk on each side is italic. A line starting with a hyphen and a space is a bullet. A line starting with "1." is a numbered list item. Link text in square brackets followed by the address in parentheses makes a link. Three hyphens alone on a line make a horizontal line.
10. Create a Hello World HTML file. Make a new file named helloWorld.html. Type an exclamation point and press Tab; this Emmet shortcut builds the whole HTML skeleton for you. Inside the body, add a level-one heading reading "Hello, World!" and a paragraph reading "This is my first web page." Save.
Code: <h1>Hello, World!</h1>
This is the main heading element with the text Hello, World! inside it.
11. Preview the page. Right-click the file and choose Show Preview (Live Preview), or choose Go Live in the Status Bar (Live Server). That preview is your own computer rendering the page. GitHub will show the HTML as code, not as a working page. Turning a repo into a live website is called GitHub Pages, covered in a later lesson.
12. Git status letters. New files show U for Untracked, meaning Git sees them but is not tracking them yet. After you commit, Git tracks them, and editing them later shows M for Modified. The full list: U Untracked, M Modified, A Added (staged), D Deleted, R Renamed.
13. Commit and push. In GitHub Desktop the Changes tab lists myFirstMarkdown.md and helloWorld.html as new files. Write the commit message "Add markdown and Hello World HTML files", choose Commit to main, and then, because the repo is already on GitHub, choose Push origin (not Publish).
14. Check the "after" state. Refresh the GitHub tab. The commit count has gone up, the new files appear, myFirstMarkdown.md is displayed as formatted text because GitHub renders Markdown, and helloWorld.html shows as code, which is expected.
15. Optional: update a tracked file. Add a line to README.md and save; its letter becomes M. Commit with the message "Update README", push, refresh GitHub, and the README on the home page re-renders with your new text.

Key terms:
VS Code — Visual Studio Code, the code editor used in class.
Activity Bar — the far-left column of view buttons (Explorer, Search, Source Control, Extensions).
Explorer — the VS Code panel listing your project's files and folders.
Editor — the main typing area.
Tabs — your open files; a dot means unsaved changes.
Status Bar — the bottom strip with info and buttons such as Go Live.
Command Palette — Ctrl+Shift+P; run any command by typing its name.
Extension — an add-on that gives VS Code new features.
Live Preview — Microsoft extension that previews web pages inside VS Code.
Live Server — Ritwick Dey extension that opens your page in a browser and auto-refreshes on save.
Emmet — the shortcut system behind typing ! then Tab to generate an HTML skeleton.
Markdown — a simple text format (.md files) that GitHub displays as formatted text.
lowerCamelCase — the class file-naming style, such as myFirstMarkdown.md.
GitHub Pages — GitHub's feature for publishing a repo as a live website (later lesson).
Push origin — the GitHub Desktop button that sends new commits to an already published repo.

What you are asked to do:
The "You did it when" checklist:
1. You can point to VS Code's Explorer, Editor, Extensions, and Command Palette.
2. Your extensions (Live Preview, Live Server, Convert Markdown to PDF) are installed.
3. You opened the github-desktop-test repo in VS Code and checked its "before" state on GitHub.
4. You created myFirstMarkdown.md and helloWorld.html and previewed each.
5. You understand the U, M, A, D, and R letters.
6. You committed and pushed, then saw the "after" on GitHub: higher commit count, new files present, Markdown rendered.
7. You can say the loop out loud: edit, save, commit, push, refresh.

Watch out for:
- Check the extension publisher before installing so you get the right one.
- Open the whole folder in VS Code, not a loose file, or the Explorer may look empty.
- After the first publish, use Push origin; there is no second Publish.
- An HTML file on GitHub shows as code, not a web page. That is normal until GitHub Pages.
- Use lowerCamelCase and exact file names.
- An unsaved file (dot on its tab) will not show up as a change to commit. Save first.
