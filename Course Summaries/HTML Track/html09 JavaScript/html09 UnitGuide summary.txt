In one sentence:
This is the map of the merged html09 JavaScript unit: it lists the six segments (09a through 09f), which files go with each, what is in and out of scope, and a warning about whether the browser console works on student computers.

Main ideas:
1. The unit is a merger. It combines what used to be two lessons, html09 JavaScript Basics and html10 JS DOM and Interactivity, rebuilt under a "v2 master plan." That is why some files in this folder still say "Lesson 10" or "HTML10" in their titles.
2. The unit covers ODE competencies 6.3.1, 6.3.2, 6.3.3, and 6.4.7, and runs about 5 to 6 class periods.
3. Segment 09a and 09b: JavaScript basics. Topics are the script tag, the console, variables, functions, and comments, ending with the Mad Libs project. Materials: html09_Slides, html09_Walkthrough, html09a_Task, html09b_Task.
4. Segment 09c: DOM core. Topics are selecting an element, changing its content and styles, event listeners, and classList.toggle. Materials: html09_DomSlides, html09_DomWalkthrough (Parts 1 to 4 and Part 6 only), and html09c_Task.
5. Segment 09d: Feature day one, a dark mode toggle added to the student's real website. Materials: html09_FeatureDaysSlides and Part 1 of html09_FeatureDays_Walkthrough.
6. Segment 09e: Feature day two, a mobile hamburger navigation menu on the student's real site. Materials: the same slides and Part 2 of the Feature Days walkthrough.
7. Segment 09f: Client-side form validation on the form built in html08. This segment carries competency 6.4.7. It also includes a "describe-level" discussion of what a server, a database, or a web service does with submitted data (students explain it, they do not build it). Materials: the validation section of the DOM walkthrough, html09d_Task, and html09_FeaturesDIYTask. A teacher solution is kept in a teacher folder (teacher/html09_Features_Solutions), which is not in this folder.
8. Scope decisions, which the guide says not to drift from:
- Hover effects are CSS, using the :hover pseudo-class from html06. The old JavaScript hover part of the walkthrough is retired. Competency 6.2.7 is treated as a CSS skill.
- Template literals are shown once but not drilled. String concatenation with the plus sign is the form that gets tested.
- The FAQ accordion and other show/hide patterns moved to html09_ExtensionTask.md as optional extra practice.
- No fetch, no APIs, and no frameworks in this unit; that is spring content.
9. Console warning. Developer tools are disabled on student machines. If that includes the F12 console, the console.log sections of the basics walkthrough will not work as written, so the teacher must check a student machine first. The fallback is an "output div" pattern: put an empty div with the id output on the page, and write a small helper function named say that adds each message to that div's text.
Code: function say(msg) { document.getElementById('output').textContent += msg + "\n"; }
In words: the function say takes a message, finds the element whose id is output, and adds the message plus a line break to the end of its text. Students then write say("Hello, world!") everywhere the walkthrough says console.log(). The guide points out a bonus: students meet the textContent property on day one, which makes the later DOM segment easier.
10. Why there are two feature days. Dark mode and the hamburger menu are the same move, classList.toggle, used twice. The guide's philosophy is that repeating a small toolkit beats covering a large one. Both features stay on the student's real site and are required in the html11 hand-coded build.

Key terms:
DOM — the Document Object Model, the browser's live model of the HTML page that JavaScript can change.
classList.toggle — a JavaScript method that adds a class to an element if it is missing and removes it if present.
textContent — a property holding the plain text inside an element; setting it replaces or adds text.
template literal — a string written between backtick characters that can insert values; shown once in this unit, not drilled.
concatenation — joining strings with the plus sign; the tested form in this unit.
:hover — the CSS pseudo-class for hover styling; the correct tool for hover effects.
output div — the fallback pattern where messages are written onto the page instead of the console.
client-side validation — checking form input in the browser with JavaScript before it is sent.
feature day — a class period spent adding one real feature to the student's own website.

Watch out for:
- If the console is blocked on school machines, use the say() output-div method in place of console.log().
- Do not build hover effects in JavaScript; the unit treats that as a CSS job.
- Know concatenation with the plus sign well, because that is what is tested.
- Dark mode and the hamburger menu must stay on your site because html11 requires them.
Heads up: html09_DomWalkthrough has no form validation section, even though this guide sends 09f there. Study validation from html09_DomSlides, html09_DomStudyGuide, and html09d_Task instead.

Connects to:
html06 (CSS :hover), html08 (the form that gets validated), and html11 (the hand-coded build that must include dark mode and the hamburger).
