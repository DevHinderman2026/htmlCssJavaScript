Type of document: DIY task (project: Mad Libs Story Generator)

In one sentence:
This is the project for the basics half of the unit: build a Mad Libs page that stores words in variables, combines them into a story with a function, and shows the story on the page, graded on a 100-point rubric.

Main ideas:
1. Mad Libs is a word game: collect random words, plug them into a story template, and get a funny result. Your page stores words in JavaScript variables, uses a function to build the story, and displays the result on the HTML page, not just in the console.
2. Learning goals: use variables of different types; write and call functions with parameters; use template literals to build strings; practice connecting HTML and JavaScript; and make an interactive, dynamic page.
3. Example variables given: adjective1 'silly', adjective2 'mysterious', noun1 'penguin', noun2 'spaceship', verb1 'juggle', verb2 'explore', adverb 'frantically', and number 42.
4. Example function structure:
Code: function generateMadLibsStory(adj1, noun1, verb1, adj2) {
In words: this starts a function named generateMadLibsStory with four parameters. Its body returns a template literal sentence: Once upon a time, a (adj1) (noun1) decided to (verb1) in a very (adj2) way!
5. Example of displaying the result:
Code: let myStory = generateMadLibsStory(adjective1, noun1, verb1, adjective2);
In words: this calls the function with four of your variables as arguments and saves the finished story in myStory.
Code: document.getElementById('storyOutput').textContent = myStory;
In words: this finds the element whose id is storyOutput and replaces its text with the story, so it appears on the page.
6. Example of the finished page: a title like "Mad Libs Story Generator," instructions such as "This page creates silly stories using random words and JavaScript!", a clear story area, a funny story at least 2 to 3 sentences long, and well-commented JavaScript. The sample output is three silly sentences about a purple penguin juggling in mysterious pajamas, singing 42 songs, and dancing with a sparkly robot.

Key terms:
Mad Libs — a word game that fills blanks in a story with random words.
DOM method — a JavaScript tool for finding or changing page elements, like document.getElementById().
document.getElementById() — finds the one element with a given id.
textContent — property that sets the plain text inside an element.
innerHTML — property that sets the HTML inside an element, so tags like strong or br are rendered.
prompt() — a browser function that pops up a box asking the user to type something.
onclick — an HTML attribute that runs JavaScript when an element is clicked.
camelCase — naming style like storyOutput.

What you are asked to do:
Requirements:
1. HTML structure: a valid HTML5 page with DOCTYPE, head, and body; a title describing your Mad Libs game; instructions telling the user what the generator does; a div or p element with an id (such as id="storyOutput") where the story shows; and a link to an external JavaScript file (not inline).
2. JavaScript variables: at least 8, including at least 2 adjectives, at least 2 nouns, at least 2 verbs, and at least 2 other words (adverbs, colors, foods, numbers, and so on).
3. JavaScript function: a descriptive name (like generateMadLibsStory or createFunnyStory); parameters for at least 4 of your variables; a template literal that combines all the parameters into a story; and it must return the story as a string.
4. Display: call the function with your variables as arguments, store the result in a variable, and use document.getElementById() or a similar DOM method to put the story into your HTML element. The story must display on the page, not only in the console.
5. Comments: a comment for what each variable stores, a comment above the function saying what it does, and a comment explaining how the story is displayed.
6. Code quality: camelCase for all variable and function names; meaningful names (not x, y, a, b); proper indentation; and valid HTML and JavaScript.
Stretch goals (optional, pick one or more):
1. Add a button that makes a new story with different words each click, for example a button with onclick="generateNewStory()".
2. Write several story functions and randomly pick one to show.
3. Ask the user for words with prompt(), for example let userAdjective = prompt('Give me an adjective:');
4. Style the story with CSS (color, fonts, borders).
5. Use innerHTML instead of textContent to add HTML formatting such as paragraphs, bold text, and line breaks.
6. Write a longer story with more than 8 variables.
Testing checklist before submitting: the HTML is valid and displays in a browser; the JavaScript file is linked and loads; variables use let or const; the function takes parameters and uses a template literal; the story shows on the page; there are no console errors in F12 Developer Tools; code is commented and uses camelCase; and the story makes sense and is funny or creative.
Deliverables: two files, html09_DIYTask_[YourName].html and html09_DIYTask_[YourName].js. Or, if preferred, a single html09_DIYTask_[YourName].html with an inline script.
Rubric, 100 points total:
- HTML structure (valid HTML5, proper tags, id for output): 20 points.
- Variables (8 or more, multiple types, let or const, meaningful names): 20 points.
- Function (parameters, template literal, return; must take 4 or more parameters): 20 points.
- Display on page (DOM manipulation; story must appear in the HTML): 20 points.
- Comments and code quality (camelCase, indentation, clarity): 10 points.
- Creativity and humor: 10 points.
Getting started steps: make the HTML file with a title, instructions, and output area; make a JavaScript file with at least 8 word variables; write a function taking those words as parameters; call it and display the result; test in the browser; then add stretch goals if you want.

Watch out for:
- Showing the story only with console.log does not meet requirement 4.
- If you link the external script in the head, it may run before the output element exists; placing the script tag at the end of the body avoids that (the DOM Study Guide lists "accessing elements before the page loads" as a common mistake).
Correction: submit two files with an external JavaScript file, as requirement 1 says ("not inline"). The Deliverables section also allows one file with an inline script, but the two-file version satisfies both parts of the document, so it is the safe choice.
Heads up: this project does require a template literal in the story function, even though the Unit Guide tests concatenation with the plus sign; use a template literal here, and study concatenation for tests.
- Stretch goal 1 uses the onclick attribute, but the DOM lessons later recommend addEventListener instead of inline event handlers.
