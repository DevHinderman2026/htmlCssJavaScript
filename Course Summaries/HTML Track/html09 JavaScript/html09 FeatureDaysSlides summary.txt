In one sentence:
These Feature Days slides show that dark mode and a mobile hamburger menu are the same JavaScript move, select, listen, toggle, and let CSS finish, and that both go on your real site.

Main ideas:
1. The theme of the day: "Two Real Features, One Move." Everything is select an element, listen for an event, toggle a class, and let CSS do the rest.
2. Dark mode is a CSS lesson in disguise. Colors are stored as CSS custom properties (variables). On :root, --bg-color is white (#ffffff) and --text-color is near-black (#1a1a1a). A rule for body.dark-mode (the body when it has the class dark-mode) swaps them: background near-black, text light gray (#eeeeee). The body rule uses var(--bg-color) for its background and var(--text-color) for its text. So adding one class to body re-themes the whole page; the cascade does the work and JavaScript just flips a switch.
3. The whole dark mode JavaScript is three statements.
Code: const toggleBtn = document.getElementById('theme-toggle');
In words: select the button whose id is theme-toggle.
Code: document.body.classList.toggle('dark-mode');
In words: this line runs inside a click listener on toggleBtn; each click adds the dark-mode class to body if missing, or removes it if present.
Polish ideas: update the button's label, and add a CSS transition so the change fades.
4. The hamburger: same move, new problem. The CSS is mobile-first: nav ul is display none (hidden on phones), and nav ul with the class open is display block. Inside a media query for screens at least 768 pixels wide, nav ul becomes display flex (always visible on desktop) and the button with id nav-toggle is display none (gone). The media query decides who sees the button; the toggle decides whether the menu is open.
5. One new idea: announce your state. In the nav button's click listener, step by step: toggle the open class on the nav list; then check whether the list now contains the open class and store that true or false in isOpen; then set the button's aria-expanded attribute to isOpen. A button that shows and hides content should tell assistive technology, such as a screen reader, whether it is open. That is what aria-expanded does, and it is why a real button element is used.
6. Hover is not JavaScript. To change a link on hover, use CSS, for example nav a:hover with gold text. JavaScript events are for what CSS cannot do: clicks, input, and changing content.
7. Today's build: add dark mode to your site (custom properties plus toggle); add the hamburger to your site (mobile-first CSS plus toggle); and keep both, because they are required in the html11 project. Fast finishers can do the extension menu: accordion, scroll-to-top, lightbox, and tabs.

Key terms:
CSS custom property — a CSS variable whose name starts with two hyphens, like --bg-color, read with var().
var() — CSS function that uses a custom property's value.
:root — CSS selector for the top of the page (the html element), where global variables are usually defined.
cascade — CSS's rules for which style wins; here, the more specific body.dark-mode values override the :root ones.
classList.toggle() — adds a class if missing, removes it if present.
classList.contains() — returns true if the element has a given class.
media query — a CSS block that applies only when a condition, like a minimum screen width, is true.
mobile-first — writing the phone styles first, then adding wider-screen rules in media queries.
hamburger menu — a button, usually shown as three stacked lines, that opens a hidden nav on small screens.
aria-expanded — an accessibility attribute on a button that says whether the content it controls is open (true) or closed (false).
setAttribute() — sets an HTML attribute's value from JavaScript.
transition — CSS property that animates a change smoothly.

Watch out for:
- Use a real button element for toggles so keyboard and screen-reader users can use them.
- Always update aria-expanded when the menu opens or closes.
- Hover effects belong in CSS, not JavaScript.
