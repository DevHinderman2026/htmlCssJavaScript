In one sentence:
These slides teach how JavaScript reaches into the page through the DOM: selecting elements, changing their content and styles, responding to events, validating a form, and showing or hiding things with classList.

Main ideas:
1. The deck is still titled "Lesson 10: JS DOM and Interactivity," with sub-lessons 10a (DOM manipulation) and 10b (events and validation). In the merged unit this is segment 09c and part of 09f.
2. What is the DOM. DOM stands for Document Object Model. It is a tree structure that represents your HTML, where each element is a branch or leaf. JavaScript can read and change it, and changes show up on the page immediately.
Code: document.getElementById('myButton').innerHTML = 'Clicked!';
In words: find the element whose id is myButton and replace what is inside it with the word Clicked!.
3. Selecting elements, three main ways:
- By id, the fastest: document.getElementById('header') returns that one element.
- By CSS selector: document.querySelector('.item') returns the first element with class item; document.querySelectorAll('.item') returns all of them as a list.
- By tag name: document.getElementsByTagName('a') returns all the links.
4. Changing content and styles:
- element.textContent = 'New text here'; replaces the plain text.
- element.innerHTML = '<strong>Bold text</strong>'; replaces the inside with real HTML; the slide says to be careful with this.
- element.style.color = 'blue'; element.style.backgroundColor = 'yellow'; and element.style.display = 'none'; set inline styles; display none hides the element.
5. Events are things that happen on a page: click, hover, typing, submitting, loading, and so on. The best practice is an event listener.
Code: button.addEventListener('click', function() { console.log('Button was clicked!'); });
Step by step: after selecting the button with getElementById('myBtn'), this tells the button to listen for clicks. When a click happens, the unnamed function inside runs and logs a message. The slide shows the inline alternative, an onclick attribute written on the button tag, and marks it "not recommended."
6. Common events, in words: click fires when the user clicks an element; mouseover when the mouse enters it; mouseout when the mouse leaves it; submit when a form is submitted; change when an input's value changes; and keydown when a key is pressed.
7. Simple form validation. Step by step: read the email field's current value with document.getElementById('email').value and store it. If the value is exactly equal to an empty string, show an alert saying "Email is required!" and return, which stops the code. Next, if the email does not include the at sign, alert "Please enter a valid email!" and return. The not operator is the exclamation mark before email.includes('@').
8. Show and hide error messages with classList. The setup is a paragraph with id errorMsg and class hidden, and a CSS rule where the hidden class sets display to none. Then classList.add('hidden') hides it, classList.remove('hidden') shows it, and classList.toggle('hidden') flips it on or off.
9. Hover effects, CSS versus JS. The CSS way is simpler: a button:hover rule sets a dark blue background. The JavaScript way uses a mouseover listener to set the background to dark blue and a mouseout listener to set it back to blue; the slide calls this "more control."
10. Building an interactive element: an FAQ accordion. When the question with id q1 is clicked, the code gets the answer with id a1. If the answer's style.display is 'none', it sets it to 'block' (showing it); otherwise it sets it to 'none' (hiding it).
11. Key takeaways: select with getElementById() and querySelector(); change content with innerHTML or textContent; change styles with element.style.property; respond to events with addEventListener(); validate forms before submitting; and use classList to manage visibility and styling.

Key terms:
DOM (Document Object Model) — the tree of objects the browser builds from your HTML, which JavaScript can change.
document — the JavaScript object representing the whole page.
getElementById() — selects the one element with a given id.
querySelector() — selects the first element matching a CSS selector.
querySelectorAll() — selects every element matching a CSS selector, as a list.
getElementsByTagName() — selects all elements with a given tag name.
textContent — the plain text inside an element.
innerHTML — the HTML inside an element; tags you assign are rendered.
style — an element's inline styles; CSS property names are written in camelCase, like backgroundColor.
event — something that happens on the page, like a click.
addEventListener() — attaches a function that runs when a given event happens.
click, mouseover, mouseout, submit, change, keydown — common event names.
value — the current text in a form input.
includes() — checks whether a string contains some text.
alert() — pops up a message box.
return — here, stops the rest of the function from running.
classList — an element's list of classes, with add(), remove(), and toggle() methods.
accordion — a list of questions whose answers expand and collapse when clicked.

Watch out for:
- innerHTML renders any tags you give it, so be careful; use textContent for plain text.
- Use addEventListener, not inline onclick attributes.
- Use triple equals (===) to compare, not a single equals sign.
- The return inside the validation example only works inside a function (such as an event listener); on its own at the top level of a script it would be an error. The slide shows only the inside part.
Correction: hover effects belong in CSS with the :hover pseudo-class; the newer Unit Guide retires the JavaScript hover exercise. The "Hover effects: CSS vs JS" slide still shows JavaScript hover as an option, but follow the Unit Guide.
- The accordion example here is now optional; the Unit Guide moved accordions to the Extension Task.
