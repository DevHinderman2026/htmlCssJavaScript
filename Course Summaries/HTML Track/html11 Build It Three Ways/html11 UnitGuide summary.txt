In one sentence:
This guide lays out the whole Build It Three Ways project: its purpose, its seven segments with their materials, how it is graded, and what is still undecided.

Main ideas:
1. This is the course's culminating block and replaces the old capstone project. The idea is one client scenario, three builds of the same site, and one professional verdict about which build the client should use.
2. Ohio (ODE) competencies covered: 2.9.1 to 2.9.6 (the proposal), 2.12.1 to 2.12.6 (testing and acceptance), 2.13.1 to 2.13.6 (rollout and handoff), 6.5.3, 6.5.4, and 6.5.6, plus everything the hand-coded build pulls together.
3. The premise: real web professionals do not hand-code everything. They choose between hand-coding, AI generation, and site builders based on the client, the budget, and the job. You do all three for the same client, then judge them like a professional with a testing checklist and a comparison matrix.
4. The segments, about 8 working days in total (the guide says this is content, not a calendar):
- 11a: kickoff, client brief, and mini-proposal covering scope, audience, objectives, timeline, and deliverables. Materials: Kickoff Slides, Client Scenarios, Proposal Template.
- 11b: the hand-coded entry. Polish your semester site against the client brief. Dark mode and a mobile nav are required (both from html09). Material: your own repository.
- 11c: the AI build. Direct an AI, naming Bootstrap components from the component menu, then critique its output line by line. Materials: AI Build Guide, plus the enrichment Bootstrap Basics folder as the component menu.
- 11d: the builder builds. Google Sites, then WordPress.com, a real content management system you configure hands-on (competency 6.5.4). Material: Builder Guide.
- 11e: media day. Web-optimized images and an SVG logo. Material: Adobe Media Day, which is marked as a placeholder.
- 11f: test and compare. The same usability checklist on all three builds, then fill in the matrix. Material: Compare Matrix.
- 11g: handoff writeup and 5-minute presentations. Material: Handoff Template.
5. Grading uses a rubric with criteria bands and no points, consistent with course policy. Worked examples of a proposal, an AI critique, and a matrix with verdict exist for the teacher to show after students draft their own. The old capstone rubric is source material for the quality bands of the hand-coded build.
6. Open items still to be decided: which AI tool 11c will use (the guide is written to work with any tool until accounts are settled); which Adobe version 11e will use (desktop apps, web apps, or Adobe Express); and a check that WordPress.com and Google Sites are not blocked by the district's web filter before 11d starts.

Key terms:
Culminating block — the final, pulling-it-all-together project of the course.
Client scenario — the fictional (or approved real) organization you build for.
Hand-coded — written yourself in HTML, CSS, and JavaScript.
Site builder — a no-code tool like Google Sites that builds pages from drag-and-drop blocks.
CMS — content management system, such as WordPress, that lets non-coders update a site.
Comparison matrix — a grid comparing the builds on the same dimensions.
Handoff — the document that gives the finished site to the client with instructions.
Criteria bands — rubric levels that describe quality instead of giving point scores.

What you are asked to do:
Complete all seven segments, 11a through 11g, using the materials listed above; each segment's own document gives the file to commit.

Watch out for:
- Dark mode and mobile nav are required in the hand-coded build.
- The media day file is only a placeholder and may change.
Heads up: the rubric and exemplars (html11_Rubric.md, html11_Rubric_DRAFT.md, and an exemplar folder) are in a teacher folder that is not in these files, so the exact rubric bands cannot be known from here. Meet every requirement in each segment's own document, and ask Mr. McMaster to see the rubric if you want the bands.
