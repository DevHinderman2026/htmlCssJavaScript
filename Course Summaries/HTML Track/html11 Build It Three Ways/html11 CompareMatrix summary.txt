Summary of: html11_CompareMatrix.md
Course: HTML CSS JavaScript track
Lesson: html11 Build It Three Ways
Type of document: template (segment 11f, test and compare)

In one sentence:
This template has you run the same usability checklist on every build, fill in a comparison matrix, and write a one-paragraph verdict on which build your client should use.

Main ideas:
1. Step 1 is the same usability test run on all three builds: hand-coded, AI, and builder. Use the same standards with no favoritism; you are a professional evaluator now, not a proud parent.
2. Step 2 is a matrix that compares four columns (hand-coded, AI build, Google Sites, WordPress) across seven dimensions.
3. Step 3 is the verdict. There is no single right answer, only a well-argued one. The honest answer is often a combination, or "it depends," for example on whether the league secretary really will update the site.

Key terms:
Usability checklist — a fixed list of tests applied equally to every build.
Pass, partial, fail — the three possible results for each checklist item.
W3C validator — the official online tool that checks HTML for errors.
Comparison matrix — a grid of builds against dimensions like cost and control.
Verdict — your recommendation, backed by evidence from the matrix.

What you are asked to do:
Step 1: for each build, record pass, partial, or fail plus one sentence for each checklist item:
1. Every nav link works, with no dead ends.
2. Readable in a phone-width window.
3. Every image has meaningful alt text.
4. Heading hierarchy is logical: one h1 and no skipped levels.
5. The form is labeled and usable.
6. The table reads correctly.
7. Load feel: nothing feels noticeably heavy or slow.
8. Consistent look across pages.
9. W3C validator results for the hand-coded and AI builds. Builders will not give you clean access to their markup; note that fact too.

Step 2: fill in every cell of the matrix. Columns: Hand-coded, AI build, Google Sites, WordPress. Rows:
1. Build time.
2. Control over the result.
3. Code quality (if visible).
4. Accessibility findings.
5. Whether a non-coder can maintain it.
6. Cost to run it for real.
7. Best suited for what.

Step 3: write one paragraph answering which build your client should actually use, and why. Reference at least three matrix rows.

Commit html11_Comparison_lastname.md (with your last name) containing the checklist results, the filled matrix, and the verdict.

Watch out for:
- Hold your own hand-coded site to the same standard as the others.
- The verdict must cite at least three matrix rows.
- Correction: run the checklist on all four sites (hand-coded, AI, Google Sites and WordPress), because the matrix has four columns. Step 1 says "all three builds" only because it counts the two builder sites as one build.
- For a screen reader user, checklist items 3, 4, and 5 (alt text, heading order, form labels) are ones you can test directly by navigating each site by headings and form fields.
