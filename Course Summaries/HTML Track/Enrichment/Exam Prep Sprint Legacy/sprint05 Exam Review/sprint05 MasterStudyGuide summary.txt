In one sentence:
The comprehensive final study guide for the exam, gathering every testable fact from all sprints into seven sections: Bootstrap, forms, SEO and accessibility, protocols and deployment, troubleshooting and QA, business and ethics, and an Ohio competency map, plus a top-ten list and exam-day reminders.

Main ideas:

Section 1, Bootstrap and responsive design:
- Bootstrap is a popular open-source CSS framework for responsive design. Its grid is a flexible 12-column system.
- A container centers and pads content (container, or container-fluid for full width). A row is a horizontal group of columns and must be inside a container. A column is one unit of the grid whose width can change at breakpoints.
- Column classes: col gives equal widths; col-md-6 is 50 percent from medium up; col-md-4 is about 33 percent from medium up; col-lg-3 is 25 percent from large up; col-sm-12 is full width from small up and stacks on mobile.
- Offset and order: col-md-6 offset-md-3 makes a 6-column box pushed 3 columns in, which centers it. order-md-2 changes an item's position in the row from medium up.
- Breakpoints and infixes (the size letters in the class name): extra small has no infix and is under 576 pixels (the default styles); sm 576 and up; md 768 and up; lg 992 and up; xl 1200 and up; xxl 1400 and up. Mobile-first: design for phones first, then add breakpoints for larger screens.
- Components and their base classes: navbar (navigation with logo, links and collapse), card (image, title, text, button), btn (primary, success, danger variants), alert (info, warning, success, danger), badge (small status label), pagination (page numbers with next and previous), modal (pop-up dialog for forms, confirmations or messages), accordion (collapsible sections, such as FAQs).
- Utilities: spacing m-3, p-2, mt-4, pb-1; display d-flex, d-none, d-block, d-inline-block; text text-center, text-end, fw-bold, fs-5; colors text-primary, bg-light, border-danger; borders border, border-top, rounded.

Section 2, HTML forms:
- A form collects input. action is the URL that receives the data; method is GET or POST.
- GET versus POST: GET puts data in the URL query string, visible, limited to about 2000 characters, bookmarkable, often cached, less secure, idempotent (safe to repeat), for searches and filters. POST puts data in the message body, hidden, no practical limit, not bookmarkable, not cached by default, more secure, not idempotent (can have side effects), for logins and sensitive data.
- Radio versus checkbox: radio allows one choice and the group must share a name (an either-or choice, example given: gender); checkbox allows multiple and names can differ (example: interests such as sports, music, art).
- Best-practice form example: a form with action process.php and method POST, a "Contact Information" fieldset with required full name and email fields, each label linked by for and id and wrapped in a div; a "Preferences" fieldset with contact method radio buttons (phone, email) and interest checkboxes (sports, music); then a submit button and a reset button labeled Clear.
- Input types to know: text, email (validates format), password (masked), number (with a spinner), tel, url, date (picker), checkbox, radio, file (upload), submit, reset, button (generic), hidden (not displayed).
- Fieldset and legend group related controls (the example is a "Shipping Address" group with street and city). Screen readers announce the group, it organizes the form visually, and it gives better semantics.

Section 3, SEO and accessibility:
- Terms: SEO, title tag, meta description, heading hierarchy, keyword, alt text, ADA, WCAG, accessibility, screen reader, ARIA, contrast ratio (defined under Key terms).
- SEO checklist before publishing: unique title of 50 to 60 characters with the main keyword; meta description of 150 to 160 characters that is compelling and includes a keyword; one h1 stating the main topic; h2 and h3 in proper order; keywords placed naturally in the title, headings and first 100 words; descriptive alt on all images; internal links to related pages; responsive, mobile-friendly design; fast loading with optimized images and minified CSS and JavaScript; descriptive URLs with hyphens, such as example.com/web-design-tips.
- The SEO example page has a title "Web Design Tips for Beginners | Best Practices 2024", a matching meta description, one h1, h2 section headings, and an image with descriptive alt text.
- Accessibility checklist for WCAG AA: contrast 4.5 to 1 for text and 3 to 1 for graphics; everything works by keyboard; meaningful images have descriptive alt; every input has a label; proper h1 to h6 order; a skip-to-content link at the top; ARIA (aria-label, aria-describedby) for icon buttons and help text; clear, specific error messages linked to their fields; captions for video and transcripts for audio; visible focus indicators; no keyboard traps (you can move into and out of everything); the page language set on the html tag.
- Accessible form example: a username input that is required and uses aria-describedby pointing to a small help text "3-20 characters, alphanumeric only", a required password input, and a Sign In button with aria-label "Sign in to account".
Code: <input type="text" id="username" name="username" required aria-describedby="username-help">
aria-describedby tells the screen reader to also read the element whose id is username-help, the hint below the field.
- WCAG levels: A is the minimal foundation; AA is the standard industry norm that most laws require; AAA is enhanced, best-in-class.
- SEO and accessibility overlap: alt text, heading hierarchy, semantic HTML, keyboard navigation, fast loading and clear writing help both.

Section 4, protocols and deployment:
- HTTP is unsecured web communication; HTTPS is encrypted. FTP is file transfer, now replaced by SFTP. TCP/IP is the foundation of the internet. DNS converts domain names to IP addresses. SSL/TLS is the encryption. A certificate is a digital file proving a site's identity for HTTPS. Deployment is publishing a site to a live server.
- Status table: HTTP none, deprecated; HTTPS encrypted with SSL/TLS, required now; FTP none, legacy; SFTP (SSH File Transfer) encrypted with SSH, current; TCP/IP not encrypted, always used; DNS not encrypted, always used; SSL replaced by TLS; TLS is the current standard.
- HTTP sends plain text anyone can read; HTTPS encrypts with an SSL/TLS certificate. Every site must use HTTPS for security, SEO ranking (Google ranks HTTPS higher), trust (the lock icon) and compliance with privacy laws.
- DNS works like a phone book, for example example.com to 192.0.2.1; lookups take a moment and are then cached locally; DNS is not encrypted.
- TCP makes sure data arrives correctly and in order; IP routes data between computers; HTTP, HTTPS, FTP and email all run on TCP/IP.
- Git commands: once, set git config --global user.name and user.email. Start with git init (new repository) or git clone with a URL (copy an existing one). Change with git status, git add with a file name or git add . for everything, and git commit -m with a message (saves locally). Connect with git remote add origin and a URL; push the first time with git push -u origin main, then just git push. Get updates with git pull (download and merge) or git fetch (download without merging). Review with git log (history), git diff (unstaged changes) and git diff --staged (staged changes).
- GitHub Pages steps: create a repository on github.com (name it username.github.io for a user site or anything for a project site), add a README, clone it; copy in index.html, CSS and JavaScript, then add and commit; push with git push -u origin main; in Settings then Pages, under Build and deployment choose Deploy from a branch, pick main (or gh-pages), and save; after 1 to 2 minutes the site is at https://username.github.io (user site) or https://username.github.io/repo-name (project site). Example: user jsmith with repo portfolio publishes at https://jsmith.github.io/portfolio.

Section 5, troubleshooting and QA:
- Terms: bug (unexpected behavior), debugging (finding and fixing bugs), breakpoint (a point where JavaScript pauses for inspection; different from a Bootstrap breakpoint), console (shows errors and logs), inspector (shows live HTML and CSS), test case, QA, regression (a bug that comes back after being fixed).
- Top-Down: start with the page structure, check HTML validity, then CSS, then JavaScript; best for structure and layout issues. Example, a missing button: check that the tag is there, whether CSS sets it to display none, and whether JavaScript is hiding it.
- Bottom-Up: start with the error message, find the failing function, then trace who calls it; best for JavaScript errors. Example, a TypeError: find the exact line in the console, read the message, check the variable exists, check the function that creates it.
- Follow the Path: start with the user action and trace data through handlers, transformations and server changes back to the output; best for data flow. Example, a form that will not submit: check whether the submit event fires (console), whether validation passes, whether the request is sent (Network tab), and whether the server responds.
- Spot the Differences: compare working and broken versions with git diff and the inspector, look at recent changes, and revert changes to test; best when something just broke, such as a layout after an update.
- DevTools tabs: Console (errors, run JavaScript), Inspector (see and live-edit HTML and CSS), Network (requests, response times, failures), Sources (set breakpoints and step through JavaScript), Application (localStorage, cookies, cache). External tools: W3C HTML Validator (validator.w3.org), W3C CSS Validator (jigsaw.w3.org/css-validator), git diff, git log.
- Test case template: ID, title, precondition (for example "user is on the login page"), steps, expected result, actual result, status PASS or FAIL, notes.
- QA checklist: functionality (buttons, links, forms, navigation, search, filters, no broken links); compatibility (Chrome, Firefox, Safari, Edge, iOS, Android); responsiveness (mobile under 576 pixels, tablet 768, desktop 992 and up, no overlaps, readable text, scaling images); accessibility (keyboard, contrast, alt, labels, clear errors, visible focus); performance (loads in under 3 seconds, no broken images, no console errors, optimized files, smooth scrolling, no lag).

Section 6, business, ethics and professional skills:
- Copyright is automatic, lasts the author's life plus 70 years in the US, covers text, code, images, music and video, and is shown with the copyright symbol, year and name. Do not use others' work without permission.
- Trademarks protect brand names and logos; registration gives the registered symbol. Do not use company logos without permission.
- Fair use is a limited, case-by-case exception for education, criticism, commentary and parody, judged on purpose, amount used, and effect on the original's value. It is not blanket permission; Creative Commons or licensed content is safer.
- Licenses: all rights reserved (default, nothing allowed); Creative Commons CC-BY (credit required), CC-BY-SA (credit and share alike), CC-BY-NC (credit, non-commercial only), CC0 (public domain); open source code licenses MIT, GPL, Apache; royalty-free (pay once, use indefinitely).
- Best practices: cite sources, use free image sites like Unsplash and Pexels, use licensed fonts such as Google Fonts, use open-source code correctly, do not screenshot copyrighted content, and ask permission when unsure.
- ADA: the Americans with Disabilities Act of 1990, a federal law requiring equal access; Title III applies to websites; it is the business's responsibility. Lawsuits are increasing, the Department of Justice enforces it, settlements average 50,000 dollars or more, and reputation suffers. Images need alt text, videos need captions and transcripts, forms need labels and clear errors, buttons need keyboard access and clear labels, color must not be the only way to convey information, and navigation must be logical and keyboard-friendly. It benefits blind, deaf, motor-impaired and cognitively disabled users, and everyone.
- WCAG levels in detail: A is the bare minimum; AA is the industry target most laws reference, with 4.5 to 1 contrast; AAA is the highest (7 to 1 contrast), hard and expensive, not required by law. Aim for AA.
- Portfolio: 3 to 5 best projects with screenshots, descriptions, tools used and live GitHub Pages links; show variety; update regularly; quality over quantity.
- Resume: one page (two if very experienced); relevant skills, projects, education and certifications, and contact information (email, GitHub, LinkedIn); tailored to the job; no typos.
- Feedback and growth: accept criticism gracefully, ask how to improve, act on feedback, learn from mistakes, share your learning, help others.
- Professionalism: reply to messages within 24 hours, meet deadlines, report status, ask clarifying questions, be honest about your abilities, admit what you do not know, dress appropriately for interviews, and use good handshake and eye contact.
- Project management: scope (included, excluded, and scope creep; document it in the design brief); stakeholders (client, end users, team, managers; get buy-in early); timeline (start, end, milestone dates, deadlines, buffer time); milestones (checkpoints such as design approval; celebrate them); critical path (tasks that set minimum duration; delays there delay everything; non-critical tasks have slack; example Design, HTML, CSS, Test, Deploy).
- Six project phases: planning, design (wireframes, mockups, approval), development, testing, deployment, maintenance.
- Design brief components: title with version and date, then 1 client and decision-maker, 2 project overview, 3 goals and how success is measured, 4 target audience, 5 scope (included and not included), 6 deliverables, 7 timeline and milestones, 8 budget, 9 constraints and assumptions (technical, browser and device, content), 10 success criteria and metrics.

Section 7, Ohio competency map (eight units): 1 HTML and CSS fundamentals (structure, styling and inheritance, responsive basics); 2 Bootstrap and components (grid, components, CSS overrides); 3 forms and user input (accessible forms, input types and validation, submission); 4 JavaScript and interactivity (basic JavaScript, events, DOM); 5 SEO and accessibility (search optimization, ADA and WCAG, semantic HTML); 6 web technologies and protocols (HTTP and HTTPS, DNS and TCP/IP, FTP and file deployment); 7 testing, debugging and deployment (DevTools, W3C validators, cross-browser testing, Git, GitHub Pages); 8 professional development and ethics (intellectual property, ADA and WCAG, project management, portfolio and resume, design briefs).

Top ten to know: the Bootstrap grid (12 columns, container, row, col, breakpoints); forms (labels, GET versus POST, fieldset); SEO (title, meta description, h1, alt, keywords); accessibility (4.5 to 1, alt, keyboard, ARIA, ADA is law); HTTPS always; Git and GitHub Pages (add, commit, push, deploy); the four troubleshooting methods; copyright (permission, Creative Commons, limited fair use); responsive, mobile-first design tested at all breakpoints; project management (scope, stakeholders, timeline, milestones, critical path).

Key terms:
offset-md-3 — Bootstrap class that pushes a column 3 grid columns to the right from medium up.
order-md-2 — Bootstrap class that changes a column's order from medium up.
badge, pagination, modal, accordion — additional Bootstrap components.
d-flex, d-none, d-block, d-inline-block — Bootstrap display utilities.
query string — the part of a URL after the question mark that carries GET data.
idempotent — safe to repeat without side effects.
SEO — making a site visible in search results.
Heading Hierarchy — h1, h2, h3 order showing importance.
Contrast Ratio — brightness difference between text and background.
ARIA — Accessible Rich Internet Applications attributes.
aria-describedby — links a field to its help text.
skip link — link that jumps to the main content.
keyboard trap — a spot keyboard users cannot leave; must not exist.
SSL/TLS — encryption for HTTPS; TLS replaced SSL.
SFTP — encrypted file transfer over SSH.
git clone, git fetch, git diff — copy a repository, download without merging, show changes.
JavaScript breakpoint — a pause point for debugging in the Sources tab.
regression — a bug returning after it was fixed.
copyright, trademark, fair use — intellectual property protections and the limited exception.
Creative Commons (CC-BY, CC-BY-SA, CC-BY-NC, CC0) — licenses that allow specific uses.
royalty-free — pay once, use indefinitely.
critical path and slack — the tasks that cannot slip, and the spare time non-critical tasks have.

Watch out for:
Exam-day reminders from the guide: keep this guide as a reference, take the practice exam several times, focus on your lowest areas, sleep well, read questions carefully, skip and return when stuck, trust your first instinct.
Heads up: ignore the competency map's "Covered in" sprint numbers, which are wrong; the real sprints are 01 Bootstrap, 02 Forms, 03 SEO and Deployment, and 04 Troubleshooting and QA. The map's eight unit numbers are this guide's own and differ from the ODE codes (such as 6.5.3 and 2.11) in the other study guides.
Correction: Top-Down means starting from the big picture and narrowing down, and Bottom-Up means starting from the smallest details (syntax, typos, an error message) and working up; this guide and sprint04 use different examples for the same idea. Likewise, a regression is a bug where something that used to work breaks after a change, and regression testing re-runs old tests after changes to catch it; this guide's "returning bug" and sprint04's definition describe the same idea from two sides.
Correction: a label names one control, so a group of radio buttons or checkboxes should be named with a fieldset and legend. The "best practices" form example instead uses a label with for="interests" that points to no id and a "Contact Method:" label linked to nothing, and it uses form-group, which was removed in Bootstrap 5 (use a spacing class such as mb-3).
Correction: a plain static HTML site does not need a Node .gitignore; the GitHub Pages step's advice to add one "for Node" can be skipped.
Correction: WCAG Level AAA contrast is 7 to 1 for normal text and 4.5 to 1 for large text, as this guide says. The sprint03 study guide's claim that 7 to 1 is "for large text" is wrong.
Correction: outside notes are not allowed during a certification exam, so study this guide before the exam rather than keeping it as a reference during it, as the original's exam-day reminder ("bookmark this guide for reference during exam") suggests.
Correction: ADA website lawsuit settlements commonly run about 5,000 to 20,000 dollars, sometimes less for small businesses, while total costs with legal fees and site fixes can be much higher; figures vary a lot by source. The guide's "settlements average 50,000 dollars or more" is overstated, but the point stands that inaccessible sites create legal and financial risk.
Correction: HTTP is not deprecated; it still works, but browsers mark HTTP pages "Not secure," so always use HTTPS. The protocol status table wrongly lists HTTP as deprecated.
