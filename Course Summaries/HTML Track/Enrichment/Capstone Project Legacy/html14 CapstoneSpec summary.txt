In one sentence:
This is the full student-facing assignment for the html14 capstone: build, test, and publish a multi-page responsive website that shows every skill from the course.

Main ideas:
1. This is the final project for the 10-week Web Design course. It takes 5 to 6 class sessions (about 10 to 12 hours of lab work). It may be a group or individual project, as the instructor decides. The deliverable is a live website on GitHub Pages plus its GitHub repository.
2. Project goals: plan with UX and UI principles (wireframes, sitemap, color and font plan); write semantic, valid HTML5 on multiple pages; style with custom CSS including responsive techniques; add JavaScript interactivity such as form validation; follow accessibility and SEO best practices; test and validate; deploy to GitHub Pages; and reflect on the process.
3. Ten theme ideas are offered, or you may create your own: small business (coffee shop, salon, fitness studio, photography, tutoring); portfolio; nonprofit or school organization; restaurant or cafe; personal brand or resume; local business directory; e-commerce product showcase with no real checkout; event or conference site; blog or resource hub; game or hobby fansite.
4. The work is split into six sessions, each with a goal and a deliverable (listed in full below).
5. Grading uses a rubric covering HTML structure, CSS styling, responsive design, JavaScript and forms, content and media, SEO and accessibility, and deployment and testing. Details are in html14_Rubric.md.
6. Tips for success: plan first; write mobile styles first and add media queries for larger screens; test constantly in different browsers and sizes; use Chrome DevTools (Console, device emulation, Lighthouse); build accessibility in from the start; commit to GitHub often with small, meaningful commits; validate as you go; and check the example solution if stuck.
7. Resources: validator.w3.org for HTML, jigsaw.w3.org/css-validator for CSS, fonts.google.com, coolors.co or color.adobe.com for colors, picsum.photos or placeholder.com for placeholder images, Chrome DevTools device mode (F12, then Control plus Shift plus M), the Lighthouse tab in DevTools, MDN Web Docs, and W3Schools.
8. Academic integrity. Allowed: using course materials and example solutions as reference; third-party libraries like Bootstrap or jQuery with attribution; stock images, fonts, and icons with proper licenses. Not allowed: copying another student's code, using AI code generators to write your code, or submitting code you do not understand.

Key terms:
Sitemap — a map of all the pages in a site and how they link together.
Wireframe — a simple layout sketch of a page, not pixel-perfect.
Semantic elements — tags that describe meaning, such as header, nav, main, article, section, aside, footer.
External stylesheet — CSS kept in a separate .css file instead of inline styles.
Viewport meta tag — the tag that makes pages scale correctly on phones.
Code: <meta name="viewport" content="width=device-width, initial-scale=1.0">
This line tells the phone browser to use the device's real width and start at normal zoom.
CSS custom properties — CSS variables used for colors and other repeated values.
Media query — CSS that applies only at certain screen widths.
Picture element (written <picture>) — an HTML element for serving different images at different screen sizes.
Meta description — a page summary for search results, here 100 to 160 characters.
WCAG AA — the accessibility standard level required for color contrast.
Lighthouse — the DevTools audit that scores performance, accessibility, best practices, and SEO.
GitHub Pages — free hosting for a website stored in a GitHub repository.

What you are asked to do:
Required checklist, Structure and Pages:
1. At least 4 pages: Home, About, Services or Portfolio, and Contact.
2. All pages linked by a working navigation menu that is the same on every page.
3. Semantic HTML5 elements (header, nav, main, article, section, footer, and so on).
4. Proper document structure: DOCTYPE, html, head, body.
Styling:
5. An external CSS stylesheet, not inline styles.
6. Your own custom CSS; Bootstrap is optional and only supplementary.
7. A consistent color palette of at least 3 colors.
8. At least 2 fonts, one for headings and one for body text.
9. A professional, cohesive design.
Responsive Design:
10. Works on desktop (1024 pixels and up), tablet (600 to 1024), and mobile (under 600).
11. Use CSS media queries or the Bootstrap grid, or both.
12. Responsive images that scale with the viewport or use the picture element.
13. Navigation that adapts on small screens (hamburger, collapsible, or stacked).
Forms and Interactivity:
14. At least one form, such as contact, newsletter, or feedback.
15. At least 3 input fields with appropriate types and labels.
16. JavaScript validates before submission: required fields not empty; email format valid if there is an email field; at least one other rule such as phone format or minimum length.
17. The user gets feedback (alert, message, or DOM update) on failure or success.
Content and Media:
18. At least one data table (pricing, schedule, menu, team, and so on).
19. Descriptive alt text on all images.
20. Optimized images (reasonable size and format).
21. Real content for your theme, no "Lorem ipsum" placeholder text.
22. At least 3 to 4 images across the site.
SEO and Accessibility:
23. Descriptive title tags on every page, under 60 characters.
24. Meta descriptions on every page, 100 to 160 characters.
25. Correct heading order: one h1 per page, then proper h2 and h3 structure.
26. Color contrast meets WCAG AA.
27. Keyboard navigation works: every link and button reachable with Tab.
28. No accessibility warnings in the Lighthouse audit.
Testing and Validation:
29. HTML passes the W3C validator with no errors.
30. CSS passes the W3C CSS validator with no errors.
31. Tested in at least 2 browsers.
32. Lighthouse score of 80 or more in all categories.
33. All links work, no 404 errors.
Deployment:
34. A GitHub repository with a descriptive name.
35. Deployed live to GitHub Pages.
36. The repo is public and has a descriptive README.md.
37. All code committed with meaningful commit messages.

Session timeline:
Session 1, Planning (2 hours): choose a theme and target audience; brainstorm 4 pages and their content; create a sitemap; draw paper wireframes for each page; choose 3 to 5 colors with hex codes; choose 2 Google Fonts; list the content for each page; complete html14_PlanningTemplate.md. Deliverable: completed template plus hand-drawn wireframes.
Session 2, HTML Structure (2 hours): create index.html, about.html, services.html, and contact.html; write the HTML5 boilerplate; add the charset and viewport meta tags; add titles and meta descriptions; build a semantic header with logo and navigation; build a semantic footer with copyright, links, and contact info; add section, article, and aside where appropriate; write all text content; add image tags with alt text (placeholder services allowed); create a table on one page; create the contact form with proper input types; link all pages. Deliverable: 4 valid pages with working navigation.
Session 3, CSS and Responsive Design (2 hours): create styles.css; import and apply Google Fonts; define color variables; style the navigation (layout, colors, hover), main content, footer, table (borders, padding, alternating row colors), and form elements; add media queries for tablet (600 to 1024) and mobile (under 600); test at phone and tablet sizes; make navigation adapt; make images scale; change multi-column layouts to one column on mobile; add hover and active states; check contrast. Deliverable: a styled site that works at all sizes.
Session 4, JavaScript and Interactivity (2 hours): create script.js; validate required fields, email format, and at least 2 other rules; show error messages on failure and a success message on success; prevent submission when invalid; add at least one other interactive feature (smooth scrolling, hamburger toggle, image gallery or carousel, modal popup, scroll animations, or dynamic content switching); make sure the console shows no errors. Deliverable: working validation plus one interactive feature.
Session 5, Testing and Validation (1 hour): run the W3C HTML and CSS validators and fix all errors; test in at least 2 browsers; test on a real phone or DevTools emulation; check every link; test the form with edge cases such as empty fields and bad emails; run Lighthouse and aim for 80 or more; fix accessibility warnings; compress images. Deliverable: a valid, tested, accessible site.
Session 6, Deployment and Polish (1 hour): create a public repo with a descriptive name; add a README.md with the project title and description, the live link, a feature list, brief usage instructions, and credits for fonts, images, and other resources; push all HTML, CSS, JS, and images; enable GitHub Pages from the main branch in repo settings; test the live site; polish; complete html14_SelfAssessment.md. Deliverable: live site, public repo, self-assessment.

Submission (by the deadline):
1. GitHub repository URL (public, all code).
2. Live website URL on GitHub Pages.
3. Self-Assessment, completed and committed to the repo.
4. Planning Template showing your planning.
Expected repository contents: index.html (home), about.html, services.html (services or portfolio page with the table), contact.html (with the form), styles.css, script.js, an images folder (for example logo.png and hero.jpg), README.md, html14_PlanningTemplate.md, and html14_SelfAssessment.md.

Watch out for:
- One h1 per page and no skipped heading levels.
- No inline styles and no Lorem ipsum text.
- Validate early; errors are easier to fix when fresh.
- Correction: add at least 2 validation rules beyond required fields and email format, which satisfies both parts of this spec. The requirements checklist asks for at least one extra rule, but the Session 4 steps ask for at least 2.
