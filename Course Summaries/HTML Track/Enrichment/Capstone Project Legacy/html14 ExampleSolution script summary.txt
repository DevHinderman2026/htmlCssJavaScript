Type of document: example solution code

In one sentence:
This is the single JavaScript file shared by all four pages of the sample coffee shop site; it runs the mobile hamburger menu, validates the contact form field by field, and adds smooth scrolling and an Escape-key shortcut.

Main ideas:
1. Waiting for the page. The main setup runs inside a listener for the DOMContentLoaded event, which fires once the HTML has been read, so the script can safely find elements. It then calls a function named initializeFormValidation.
2. Hamburger menu toggle. The script finds the button with id hamburger and the list with id navLinks using document.getElementById. It checks that both exist, then adds a click listener. Each click toggles a class called active on both elements with classList.toggle. The CSS uses that class to open or close the menu and to animate the three bars into an X shape.
3. Closing the menu after choosing a link. It gets all the links inside the nav list with querySelectorAll, loops over them with forEach, and on click removes the active class from the button and the list.
4. Form setup only where needed. initializeFormValidation looks for the form with id contactForm. If it is not on the page (home, about, menu), the function simply returns and does nothing. This lets one script serve every page.
5. Handling submit. On the form's submit event, the script calls event.preventDefault() to stop the browser from sending the form and reloading. It clears any old message, then runs validateForm on all five fields.
Code: event.preventDefault();
This line stops the browser's normal action, here submitting the form, so JavaScript can decide what happens.
6. On success, the formMessage box gets the classes form-message and success and the text "Thank you! Your message has been sent successfully. We will respond within 24 hours." Then the form is cleared with reset(), all error messages are cleared, and the page scrolls smoothly to the message with scrollIntoView. A comment explains that a real site would send the data to a server at this point.
7. validateForm calls every field check and returns true only if all of them pass (they are combined with the and operator, written as two ampersands). Every check runs, so all errors show at once, not just the first one.
8. The five validation functions all follow the same pattern: read the value, trim the spaces off the ends, test it, and then either show an error (put text in the field's error span, add a class show to the span, and add a class invalid to the input) or clear the error (empty the text, remove both classes). Each returns true or false.
- validateName: empty gives "Please enter your name"; fewer than 2 characters gives "Name must be at least 2 characters."
- validateEmail: empty gives "Please enter your email address"; otherwise it tests a regular expression that requires some characters, an at sign, more characters, a dot, and more characters, with no spaces. Failing gives "Please enter a valid email address (example@domain.com)." A comment notes real email checking should also happen on a server.
- validatePhone: the field is optional, so empty is valid. Otherwise it strips every non-digit character and requires at least 10 digits, or shows "Please enter a valid phone number (at least 10 digits)."
- validateSubject: the dropdown's value must not be empty, or it shows "Please select a reason for contacting us."
- validateMessage: empty gives "Please enter your message"; under 10 characters gives "Message must be at least 10 characters."
9. Checking while the user fills out the form. Name, email, phone, and message are checked on the blur event (when you leave the field). The dropdown is checked on its change event.
10. clearErrorMessages finds every error span and every input, select, or textarea with the invalid class and resets them.
11. Smooth scrolling. For every link whose href starts with a number sign (an in-page link), a click listener finds the target element. If it exists, it prevents the normal jump and scrolls smoothly with scrollIntoView. Links that are just a bare number sign are skipped.
12. Escape key. A keydown listener on the whole document checks whether event.key equals Escape and, if so, closes the mobile menu.
13. A window load listener prints two confirmation messages to the browser console, which is useful for checking that the script is running.

Key terms:
addEventListener — attaches a function that runs when an event happens, such as click, submit, blur, change, or keydown.
DOMContentLoaded — the event fired when the HTML is fully read and elements can be found.
getElementById — finds one element by its id.
querySelectorAll — finds all elements matching a CSS selector.
classList.toggle, add, remove — turn a CSS class on or off on an element.
event.preventDefault — stops the browser's default action for an event.
trim — removes spaces from the start and end of text.
Regular expression (regex) — a text pattern used to test formats like email addresses.
textContent — sets or reads the plain text inside an element; used to write error messages.
scrollIntoView — scrolls the page so an element is visible; the smooth option animates it.
Blur event — fires when a field loses focus.
Change event — fires when a dropdown selection changes.
Console log — a message printed to the browser's developer console.

What you are asked to do:
Nothing directly; this is the model for capstone Session 4. The spec requires checking required fields, email format, at least one more rule, showing feedback, and preventing invalid submission; this script does all of those, plus the hamburger toggle as the extra interactive feature.

Watch out for:
- The success message says the message was "sent," but nothing is actually sent; there is no server.
- Accessibility gaps worth fixing in your own version: error messages and the success message are not in live regions (for example role of alert or aria-live), so a screen reader may not announce them; the hamburger button never gets aria-expanded updated, so screen reader users are not told whether the menu is open.
- Correction: the fields are checked on blur, which runs only when you leave a field, not while you type (that would be the input event). A code comment wrongly says "as user types."
- Correction: the script contains no skip link; the section labeled "Skip to main content link" only handles the Escape key. A real skip link is an HTML link at the top of the page pointing to the main content, and the example site does not have one.
- The Escape key and link clicks close the menu, which is good keyboard support.
