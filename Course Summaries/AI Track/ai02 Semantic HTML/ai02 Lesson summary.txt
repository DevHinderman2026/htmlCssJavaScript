Lesson: ai02 Semantic HTML
Type of document: lesson

In one sentence:
This lesson starts your music website by having Claude build its home page, index.html, using semantic page regions, two lists, and strong and em, with no styling yet.

Main ideas:
- From this lesson on, you build one site about your music. This lesson is the home page.
- The page uses five page regions: header, nav, main, section, and footer. There is no styling yet; the focus is on meaning and structure.

Step 1, Decide:
1. A name for your site, such as your artist name or [your name] Music.
2. Two sections for the home page, such as About My Music and Latest Tracks.
3. One list for each section: one ordered list and one unordered list. An ordered list is for things that happen in an order, such as the steps you take to make a track. An unordered list is for things with no order, such as the gear you use. Decide which section gets which list.

Step 2, Build:
- First tell Claude to make a folder called ai02_semanticHTML in your repository folder.
- Then tell Claude to make index.html in that folder with:
- A title that is your site name.
- A header element containing a heading level one with the site name.
- A nav element with four links: Home, About, Music, Contact. They can point to index.html, about.html, music.html, and contact.html.
- A main element. Inside main, two section elements, each with a heading level two and a paragraph. Section one has an ordered list; section two has an unordered list.
- A footer element with your artist name and the year.
- Somewhere in the text, one strong element for something important and one em element for something you want stressed.
- Then give Claude your content.

Step 3, Check (open index.html in Chrome):
1. Press D to move by region. You should hear banner, navigation, main, and content info, in that order. These are the names the screen reader uses for the header, nav, main, and footer. If a region is missing, have Claude fix it.
2. Press H. You should hear one heading level one, then two heading level twos.
3. Press L to move to each list. The screen reader says something like list with 3 items. Press Down Arrow to hear the items.
4. Press K to move through the links. You should hear four.

Step 4, Learn:
- Ask Claude whether it used any div elements where a semantic element would be better, and to list and fix them. A div is a generic container with no meaning; semantic elements tell the browser and screen reader what the content is.
- Then ask Claude the difference in meaning between strong and em.

Step 5, Make it yours:
- Add a third section, more list items, or anything else, then check the page again.

Step 6, Push:
- Commit with the summary Music site home page, then push.

Key terms:
semantic HTML — using elements that describe what content means, not just how it looks.
header — the element (written <header>) for the top of the page; here it holds the heading level one with the site name. The screen reader calls it banner.
nav — the element (written <nav>) for the main navigation links. The screen reader calls it navigation.
main — the element (written <main>) for the main content of the page. The screen reader calls it main.
section — the element (written <section>) for a themed group of content with its own heading.
footer — the element (written <footer>) for the bottom of the page; here it holds your artist name and the year. The screen reader calls it content info.
ordered list — a numbered list (written <ol>) for items in a meaningful order.
unordered list — a bulleted list (written <ul>) for items with no order.
strong — the element (written <strong>) that marks something as important.
em — the element (written <em>) that marks words to be stressed.
div — a generic container element with no meaning, which the lesson asks you to replace with semantic elements where possible.
D, H, L, K — screen reader quick keys for regions (landmarks), headings, lists, and links.

What you are asked to do:
Complete Steps 1 through 6 above: plan your site name, sections, and lists, have Claude build ai02_semanticHTML and index.html with every part listed in Step 2, check regions, headings, lists, and links by ear, ask Claude to fix unneeded div elements and explain strong versus em, and commit with the summary Music site home page and push.
Turn in:
1. index.html
2. Your answers to the questions in ai02_Questions.md, shared in Google Classroom.

Watch out for:
- Correction: you hear only four regions with the D key: banner, navigation, main, and content info. A section element becomes a region landmark only when it has an accessible name (aria-labelledby or aria-label), so the plain sections on this page are skipped by D. The lesson calls all five elements page regions, but its four-region D key check is what you should actually hear.
- The nav links to about.html, music.html, and contact.html point to pages that do not exist yet in this lesson.
- There should be exactly one heading level one on the page.
