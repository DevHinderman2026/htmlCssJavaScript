Course: Web Design AI track (archived version)
Lesson: ai00 Getting Started
Type of document: audio lab (screen reader audit practice, "The Moves Trainer")

In one sentence:
This lab teaches the eight standard screen reader moves, one at a time, by running them on a practice bakery page that was built correctly on purpose, so you learn exactly what a correct page sounds like.

Main ideas:
The lab uses the file ai00_PracticePage.html, a small website for "Trailhead Bakery." Because that page is correct, the lab can tell you exactly what you should hear for each move. Later labs use the same moves on your own pages.

Before you start, open the practice page in your browser. If you do not know how, ask Claude for step-by-step instructions, one step at a time. For every move, write down what you actually heard, even if it matched perfectly; the lab says "It matched" is a finding too.

1. Move 1, the page announcement. When a page opens, the screen reader speaks the page's title first. The title comes from a tag in the page's code (you build one in ai01). No command is needed. Open or reload the page and listen. You should hear "Trailhead Bakery - Practice Page," possibly followed by the browser name. Hearing a filename instead (like "ai00 underscore PracticePage dot html") would mean the page has no title.
2. Move 2, the headings list. Headings are the page's section titles and come in levels like an outline: level 1 is the main title, level 2s are major sections, level 3s are subsections. Every screen reader can gather all headings into one list with their levels. The lab calls this the single most useful check in the course, because a well-built page tells its whole story in this list. You should hear four headings: "Trailhead Bakery, heading level 1," "Our Breads, heading level 2," "Hours and Location, heading level 2," and "Weekend Specials, heading level 3." The correct shape is one level 1, two level 2 sections, and one level 3 inside a section.
3. Move 3, the region walk. Well-built pages are divided into named zones called regions or landmarks: a banner (the site header), navigation (the menu of links), main content, and a footer. Go to the top of the page (find that command too), then press your next region or landmark command until it wraps or stops. You should hear, in order: "banner," "navigation," "main," and "content information." Screen readers usually call the footer "content information."
4. Move 4, the links list. Every link on the page gathered into one list, read by link text alone. A link's text should make sense by itself; "click here" is meaningless in this list, and many people move through pages this way. You should hear three links: "Our breads," "Hours and location," and "Contact the bakery."
5. Move 5, tab through. The Tab key moves through every interactive element (links, buttons, form fields) in the order they appear in the code. This checks what a keyboard user can reach. From the top, press Tab repeatedly. You should hear the three links in the same order as the links list, then nothing more, because this page has no buttons or form fields yet.
6. Move 6, the table cell by cell. Tables have their own commands: one to jump to the next table and one to move a single cell at a time. In a correctly built table, the screen reader announces the column header with each value, so you know what each value means; a lazily built table gives bare values. Jump to the table and listen on arrival, then walk down the second column. You should hear the caption "Weekly hours," then "Hours, 7am to 2pm" and "Hours, 8am to noon." The header repeated with each cell is the sound of a table built right.
7. Move 7, read from here. Continuous reading from your position to the end. It lets you experience the page like a first-time visitor and check that the content order makes sense. From the top, let it run to the footer. You should hear, in order: the bakery name, the three navigation links, the Our Breads section with its bread list, the Weekend Specials subsection, the Hours section with the table, and the footer with the address and phone number.
8. Move 8, how lists announce themselves. Not a new command, but something to listen for. A real list element is announced as a list with an item count (for example "list of three items") and items are counted as you go. A fake list made of plain text and dashes gets no announcement and no count. That is the difference between structure and decoration. You should hear the navigation announced as a list of three items and the bread list as a list of three items.

Key terms:
Page title — text from the title tag that the screen reader speaks first when a page opens.
Heading level — the rank of a heading (1 is the main title, 2 a major section, 3 a subsection).
Region or landmark — a named page zone: banner, navigation, main, content information (footer).
Links list — a screen reader view of all links read by their text alone.
Tab through — moving through interactive elements with the Tab key.
Table caption — the title of a table announced when you land on it.
Column header — the label of a table column, announced with each cell in a correct table.
Continuous reading (read from here) — reading straight down the page from your position.

What you are asked to do:
- Open ai00_PracticePage.html in your browser.
- Perform Moves 1 through 8 in order and write what you actually heard under each one.
- Verdict: write the two-or-three-sentence verdict at the end of the lab (its prompts are in the original file); it is part of the completed AudioLab you turn in.

Watch out for:
- A filename announced instead of a title means the title is missing.
- Link text such as "click here" fails the links list test.
- Lists faked with dashes are not announced as lists.
- Tables without proper headers read as bare values with no context.
