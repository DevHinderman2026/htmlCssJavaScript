Summary of: ai00_FirstSession.md
Course: Web Design AI track (archived version)
Lesson: ai00 Getting Started
Type of document: walkthrough

In one sentence:
A recipe-style walkthrough for one sitting of about 45 minutes in which you run the whole five-step loop once: introduce the project to Claude, direct a tiny page, audit it, commit it, and save a prompt log.

Main ideas:
1. Before you start, the running check. Confirm out loud, one at a time: the Claude app is open and signed in; the screen reader is running; GitHub Desktop is open with this repository cloned; and you know where the repo's folder is. Fix any "no" before starting, and ask for help now rather than later.
2. Step 1, introduce the project (about 2 minutes). In your own words, tell Claude the arrangement: you are taking a web design course where you build sites by directing Claude and auditing the results; you will work in your webDesignAiTrack repository; Claude should save files where you say and confirm; and it should keep answers short unless you ask for detail. This is called context-setting, a professional habit that helps Claude work better.
3. Step 2, direct a tiny build (about 5 minutes). Ask Claude to create a complete HTML page titled "Hello from" plus your name, with one heading level one saying the same thing, one paragraph about what this class is, and an HTML comment at the top saying "My first directed build." Ask Claude to read you the structure before saving. If the read-back matches, ask it to save the file as hello.html in your ai00_gettingStarted folder and list the folder's files to confirm.
4. Step 3, first audit (about 10 minutes). Open hello.html in the browser (ask Claude for step-by-step instructions if needed) and run three checks:
- The page announcement: when the page opens you should hear "Hello from" and your name. A filename instead means the title did not make it into the code; tell Claude the page announces its filename instead of the title, have it fix the title element and save, then reload and listen again.
- The headings list: you should hear exactly one heading, at level 1, with your wording. More than one heading or the wrong level means the build does not match your direction; describe the difference to Claude and have it fixed.
- Read from the top: you should hear the heading and then your paragraph, and you should not hear the comment. Comments live in the code for developers; visitors never encounter them.
If anything fails, tell Claude the symptom in plain words, have it fix and save, and re-run only the check that failed. This fix-and-recheck cycle is the normal rhythm of the course; the document says it stops feeling like failure by about the third time.
5. Step 4, first commit (about 10 minutes). GitHub Desktop is the same four moves every time: switch to GitHub Desktop, where hello.html should appear in the changes list; move to the Summary field and type a short description, "First directed build"; activate Commit to main; activate Push origin. Done means pushed. Then ask Claude what you just did, in plain terms, when you committed and pushed, and later check your answer against the ConceptCheck.
6. Step 5, close the session (about 5 minutes). Ask Claude to compile everything from the session (your requests, its key answers, any fixes) into a markdown file called ai00_PromptLog.md in the ai00_gettingStarted folder. Then commit and push again, because the log is part of the turn-in.
7. That is the whole loop: brief, direct, save, audit, commit. Every later unit repeats it with bigger builds and sharper audits.

Key terms:
Context-setting — telling Claude the arrangement and your preferences at the start of a session.
Read-back — asking Claude to describe what it built before saving.
Title element — the code that sets the page title announced when a page opens.
HTML comment — a developer note in the code that is never spoken to visitors.
Commit to main — the GitHub Desktop button that records your changes.
Push origin — the GitHub Desktop button that sends commits to the online repository.
Prompt log — the session record file (here ai00_PromptLog.md).

What you are asked to do:
- Complete the running check, then Steps 1 through 5.
- Build hello.html by direction with the title, one level 1 heading, one paragraph, and the comment as described.
- Audit it with the three checks and fix any failures.
- Commit with the summary "First directed build" and push.
- Create ai00_PromptLog.md and commit and push again.
- Turn in (commit): hello.html, ai00_PromptLog.md, and your completed ai00_AudioLab.md (the moves trainer) and ai00_ConceptCheck.md.

Watch out for:
- Do not skip the read-back or the file-list confirmation.
- Hearing a filename when the page opens means the title is missing.
- If you hear the comment read aloud, something is wrong with the comment markup.
- Committing is not the end; the work is only turned in after you push.

Connects to:
