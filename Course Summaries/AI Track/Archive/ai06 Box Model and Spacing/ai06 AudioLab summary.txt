Course: Web Design AI track (archived version)
Lesson: ai06 Box Model and Spacing
Type of document: audio lab (screen reader experiment and audit, "Three Ways to Hide")

In one sentence:
This lab uses a demo page to show by ear that three CSS hiding techniques are not equal (only sr-only keeps content in the page's meaning), then has you find sr-only text on real websites and check that your restyled site still reads in the right order.

Main ideas:
The brief's twist had Claude build a hiding-demo page with four paragraphs: one visible, and three hidden, each by a different CSS technique. On screen, all three hidden ones look equally gone, but they do completely different things to the page's meaning. The lab calls telling them apart a professional skill most developers never learn properly. Setup: open the hiding-demo page. Each paragraph's text says which technique it uses (for example, "This paragraph is hidden with display none"), so what you hear identifies itself.

1. Step 1, read the whole page top to bottom. Read continuously from the top and count the paragraphs you hear, noting which ones they are. You should hear exactly two: the visible control paragraph and the one hidden with the sr-only technique. The display: none and visibility: hidden paragraphs should be completely absent: not announced, not reachable, not there.
2. Step 2, the census of what each technique did. Write what happened and what it means for each:
- display: none is absent from the audit. It removes the element from the page's meaning entirely, and nothing can reach it. You met it in ai05; now you see it used deliberately.
- visibility: hidden is also absent from the audit. The difference is visual: it leaves an empty gap on screen where the element was, like content covered by a blank sticker, while display: none closes the gap as if the element never existed. Ask Claude to describe the visual difference on the demo page between these two paragraphs, and record its answer; that gap is the entire difference.
- sr-only is present in the audit but absent from the screen. The technique positions the element off the visible page while leaving it fully in the document. It is the only one of the three that hides something visually while keeping it part of the page's meaning.
3. Step 3, find sr-only in the wild. Professional sites use sr-only text constantly, for "skip to main content" links, text labels inside icon-only buttons, and warnings like "opens in new window." Visit two major sites (a big retailer and a news site work well). On each, press Tab from the top a few times and pull up the links list. Listen for announced text that is clearly not part of the visible design; a skip-to-content link is the classic giveaway, since sites hide those until focused. Find at least one example per site and record the site, what announced, and what job the hidden text does.
4. Step 4, order check on your restyled site. This unit added spacing, cards, and a sticky header, all visual work, which should never change the order content reads in. Read your updated pages continuously from the top and compare to last week. You should hear the same content in the same order. If anything reads out of sequence, a layout rule moved it; tell Claude which section now reads before which, that the source order should not have changed, and ask it to find the rule that reordered it and fix it.

Key terms:
display: none — removes an element from the page layout and from screen readers; no gap is left.
visibility: hidden — hides an element from view and from screen readers but leaves an empty gap where it was.
sr-only (screen-reader-only) technique — CSS that moves an element off the visible page while keeping it in the document, so screen readers still read it.
Control paragraph — the visible paragraph used for comparison.
Source order — the order content appears in the HTML, which is the order a screen reader reads it.
Sticky header — a header that stays in place while the page scrolls.

What you are asked to do:
- Step 1: write which paragraphs you heard.
- Step 2: ask Claude about the visual difference between display none and visibility hidden, record the answer, and write one sentence per technique in your own words.
- Step 3: find at least one sr-only example on each of two major sites and record the site, the announced text, and its job.
- Step 4: read your restyled pages, write what you heard, and direct a fix if the order changed.
- Verdict: write the three-sentence verdict at the end of the lab (its prompts are in the original file); it is part of the completed AudioLab you turn in.

Watch out for:
- Hidden-looking content is not always hidden the same way; only sr-only keeps it for screen readers.
- display: none and visibility: hidden both remove content from screen readers.
- Layout rules must not change reading order.
