In one sentence:
This is the first-version README for the AI-directed track, explaining what the track is, how every unit is organized into three files, the unit map, the five-step workflow, and why pages are audited by audio.

Main ideas:
1. What the track is: an alternative pathway through the 145010 Web Design course built on two professional skills. The first is directing an AI to build exactly what you specify. The second is auditing web pages by audio, meaning testing them with a screen reader the way professional accessibility testers do.
2. It is not a lighter version of the course. It runs on the same schedule, covers the same state competencies, and ends at the same December exam. It trades one skill (typing syntax into an editor) for two that the README calls at least as marketable: precise technical specification, and quality auditing that most working developers never learn.
3. How each unit works: every unit has three files, numbered to match the main course (for example ai02 pairs with html02).
- BuildBrief: what to get Claude to build, plus the list of concepts your directions must use by name. The build is graded on the quality of your direction, not on typing.
- ConceptCheck: questions about how the web technology actually works. You answer in your own words, in the file. These store up the knowledge the December exam tests.
- AudioLab: the audit protocol. Each lab says in plain English what to check with the screen reader, what a correct page should sound like, and what to report. If the page fails the audit, it fails; you send Claude back to fix it and document what was wrong.
4. Unit map, mirroring the main course's numbering and pacing:
- ai00: the workflow itself, meaning the five-step loop, talking to Claude, the audit-moves trainer, and the first commit. This is where you start.
- ai01: document structure, the About Me page built by direction.
- ai02 to ai04: semantic HTML, links and navigation, and images, media, and tables.
- ai05 to ai08: CSS fundamentals, box model (including the sr-only technique), flexbox and responsive design (visual order versus reading order), and forms (forms-mode auditing).
- ai09 to ai11: JavaScript features, site quality and publishing, and Build It Three Ways. These were marked "coming." The README says ai11 is where this track's builder becomes the class's audio auditor.
- ai12: exam prep, shared with the main course's html12 materials.
5. The workflow is the five-step loop: brief, direct, save, audit, commit. It is learned once in ai00 and repeated in every unit. The ai00 WorkflowGuide is the full system, and ai00 FirstSession walks the loop end to end in one sitting.
6. Why audit by audio: a page can look right and still be built wrong, because bad structure hides under good styling. A screen reader strips the styling away and reads what the markup actually says, so structural mistakes that are invisible on screen become impossible to miss. Professional accessibility teams audit this way. In this track it is the standard quality gate: if the audit passes, the markup is genuinely correct, not just pretty.
7. Ground rule: "Make me a webpage" is not a direction; it is a wish. Every brief has a must-say list, the elements and concepts your instructions have to name. That vocabulary is the real curriculum.

Key terms:
AI-directed track — the version of the course where you direct Claude to build pages instead of typing code.
BuildBrief — the unit file describing what to build and the must-say vocabulary.
ConceptCheck — the unit file of understanding questions answered in your own words.
AudioLab — the unit file with the screen reader audit protocol.
Must-say list — the technical terms your directions to Claude are required to use.
Five-step loop — brief, direct, save, audit, commit.
sr-only technique — a CSS technique named in the ai06 unit description (text hidden visually but still read by screen readers).
Forms mode — a screen reader mode used when working in form fields; named in the ai08 description.
State competencies — the official skill standards the course covers.

What you are asked to do:
Nothing directly; this document explains the track. It tells you to start at ai00 and to use the three files (BuildBrief, ConceptCheck, AudioLab) in each unit.

Watch out for:
- Vague directions do not count; your instructions must use the technical names from the must-say list.
- A page that fails the audit fails, even if it looks fine.
- Heads up: ai09 to ai11 are listed as coming but were never added to this archive, so there are no archived notes for them. Study those topics in html09 JavaScript, html10 Site Quality and Publishing, and html11 Build It Three Ways in the HTML Track summaries.
