Summary of: ai02_BuildBrief.md
Course: Web Design AI track (archived version)
Lesson: ai02 Semantic HTML
Type of document: build brief (project task)

In one sentence:
This brief has you direct Claude to build a one-page site about a topic you care about using real semantic elements, then make Claude find and fix any generic divs it used.

Main ideas:
The brief pairs with html02 (Semantic HTML and Text Formatting).
1. What to build: a one-page website about something you actually care about, such as a band, team, game, or cause. It is one HTML file with no CSS yet. The page needs:
- A banner area with the site title.
- A navigation area with four placeholder links.
- A main content area with two distinct sections, each with its own subheading, paragraphs, and one list. One list must be ordered and one unordered; decide which content deserves which and be ready to say why.
- A footer with contact-style information.
- At least one use of emphasis and one use of strong importance inside the text.
2. The must-say list. Your directions must use these by name; that is the graded skill:
- header, nav, main, section, footer.
- Heading levels: one h1, with h2 for section headings, and say why there is only one h1.
- ol versus ul, with your reason for which content gets which.
- strong versus em, and what each means, not what it looks like.
3. The twist, which you must not skip. First drafts from AI often use generic containers where semantic elements belong. After the first build, ask Claude whether it used any div where a semantic element would be more appropriate, and have it list and fix them. Save its answer; that exchange is part of your deliverable.

Key terms:
header — the banner area at the top holding the site title.
nav — the navigation area holding the site's links.
main — the main content area of the page.
section — a distinct thematic part of the content with its own heading.
footer — the bottom area, here with contact information.
h1 and h2 — the single main heading and the section headings.
ol — ordered (numbered) list.
ul — unordered (bulleted) list.
em — emphasis, meaning stressed emphasis that changes how a sentence is read.
strong — strong importance or urgency in meaning.
div — a generic container with no meaning.

What you are asked to do:
- Direct Claude to build the page with every required part listed above.
- Use every must-say term by name.
- Do the twist: ask about divs that should be semantic elements, have them fixed, and save the exchange.
- Commit: index.html (the final page); ai02_PromptLog.md (your directions and key exchanges, compiled by Claude); and your completed ai02_AudioLab.md and ai02_ConceptCheck.md.

Watch out for:
- No CSS in this unit.
- AI first drafts often use divs where semantic elements belong.
- Choose strong and em for meaning, not appearance.

Connects to:
Pairs with html02 Semantic HTML; the result is audited in ai02 AudioLab.
